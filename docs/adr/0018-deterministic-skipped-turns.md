# 0018. Deterministic skipped turns from counted work

- Status: Accepted (budget amended 2026-10-18)
- Date: 2026-10-17

## Context

ADR 0005 made deterministic mode wait for every robot and never skip turns, so slow robots behave differently from the rumble, where classic skips the turns they are late for. A robot that loops for a long time (florent.XSeries.Xmen 0.9 in the RoboRumble corpus) also made outcomes depend on the machine. ADR 0014 gave robots a deterministic measure of their work: counted instructions as virtual time, calibrated against classic.

Classic waits for each robot about its CPU constant per turn (ten times that on turn 1, `Battle.wakeupRobots`), in whole milliseconds: `RobotPeer.waitSleeping` waits `wait(0, 999999)` once per whole millisecond of the constant, then `wait(0, rest)`, and the JDK rounds each of these up to `wait(1)`. If the robot isn't done, the turn runs without it: its last commands stay in effect. A robot that answers late gets one `SkippedTurnEvent` per missed turn, and more than 30 (240 for I/O robots) disable it (`RobotPeer.checkSkippedTurn`). Classic times only the robot's main thread between waking it and its next execute, including its event handlers.

## Decision

In deterministic mode, robots skip turns by their **counted work** instead of wall time:
- **Budget:** `TURN_BUDGET_NANOS` = 3.2 ms of counted work (virtual time, ADR 0014) per turn: how long classic really waits for a robot on the machine the virtual clock was calibrated on (OpenJDK 21, all intrinsics, as rumble clients run it). Its CPU constant there is 2.52 ms (2.54 ms on a later run), which is 3 waits of a millisecond; on Linux they take 3.28 ms (median of 2000, 3.19–3.31 ms). Classic times its own robot-side work per turn too (64 µs, ADR 0014), which isn't counted: 3.28 − 0.06 ≈ 3.2 ms. Turn 1 allows `FIRST_TURN_BUDGETS` = 7 budgets: classic waits 10 × 2 + 1 = 21 milliseconds then, 7 times the 3 of other turns. Budget and clock are part of the deterministic rules, which have a version (`rulesVersion()` on the Java side, `DETERMINISTIC_RULES` in the server).
  - **Until 2026-10-18** the budget was the CPU constant itself, 2.5 ms, and turn 1 allowed ten budgets. The constant leaves out classic's rounding up to whole milliseconds, so robots got about a fifth less time than in classic on the same machine.
  - **Other machines wait longer.** The constant varies with the machine; a slower one gets a larger constant and is slower too. Windows waits a whole timer tick (15.6 ms by default) for each `wait(1)`: on Windows (Java 8), classic waited 47 ms per turn for the same constant. The budget follows the calibration machine, a Linux rumble client, the strictest common case. On it, plain classic (real timing, 35 rounds) skipped 4 of BeepBoop's 29 755 turns and 5 of SandboxDT's; deterministic mode skips none of either.
- **Late turns:** a robot that woke for turn T and did work W before its next execute answers `k` turns late: 0 if W is below the allowance (the budget, seven times it on turn 1), otherwise `1 + (W − allowance) / budget`. The work before a round's first execute is free.
- **robocode-s:** the robot host reports W with each `Execute` (`cpu_nanos`). The server holds a late `Execute` until turn T + k and then handles it as classic mode handles a late one: the turns in between ran with the robot's last commands, it gets the `SkippedTurn` events, and over 30 it is disabled.
- **When a robot learns it skipped turns:** with its next `Tick`, as classic's `checkSkippedTurn` runs when the battle wakes it. The turn it wakes in has already run, so that turn's non-critical events are cleared too. A robot over the limit is disabled and stopped then (classic stops its thread), so its code doesn't run again. This also changed classic mode, which handled all of this one turn earlier, when the late `Execute` arrived.
- **Endless loops:** a robot that keeps computing would keep classic waiting each turn, and robocode-s until the hard limit. Its code throws instead once it did `WORK_CUTOFF_NANOS` (256 budgets, 0.82 s of virtual time) since its last turn started: then it is late for more turns than any robot may skip, so it would be disabled anyway. The count is checked at the start of every loop (a backward jump's target) and every exception handler, so robot code can't catch it for long, and it throws at the same instruction everywhere. Classic's robot side, which robocode-s runs too (ADR 0012), then handles the robot as crashed: its energy is drained. florent.XSeries.Xmen, gjr.Cephalosporin and rrh.Iwillfindyou loop like this; their corpus battles are identical to classic.
  - javac's `finally` and `synchronized` handlers are covered by their own range; they only count, or the check would throw into itself forever.
  - The checks cost little for most robots, but up to a fifth more CPU for the tightest loops (stelo.MatchupAGF: 0.68 s to 0.82 s for 10 rounds); counting itself costs that robot about half again. A check in every block doubled it; storing the count at a computed index (to check without a load) was slower still.
- **The classic oracle:** the determinism agent patches classic's `RobotPeer`. Classic still waits for every robot (`-Ddebug=true`), then leaves a late robot asleep for the `k` turns it would have been busy, so classic's own `checkSkippedTurn` sees it answer late. The robot already published its new commands before it went to sleep, so during those turns the battle keeps loading its old ones (`performLoadCommands`), as in classic, where the robot would still be computing them.
- **The oracle waits for every running robot,** not only living ones (`Battle.wakeupRobots` calls `isRunning()` where classic calls `isAlive()`), as robocode-s's server waits for a robot's final `Execute`. A robot that just died still runs its handlers; unwatched, a loop there ended at the work cutoff at a random battle time, and its drained energy changed what its bullets still gave it (rrh.Iwillfindyou).

## Consequences

- Slow robots skip turns in deterministic mode as in the rumble, the same way on every machine, and the difftest checks it against classic.
- The work of a robot's other threads counts too (the counter is per robot); classic only times the main thread. Kept deliberately: counting the main thread alone would need a per-thread counter in every block, robots with threads of their own are nondeterministic anyway, and otherwise a robot could do any amount of work in a helper thread.
- **JDK calls that grow with their arguments** count per element too, or a sort of 10 000 doubles (about 2.8 million instructions' worth of time) would count as one call, 10: unfair under budgets, and a way around them. The robot class calls a synthetic helper of its own that adds the cost and then makes the original call (`JdkCosts`). Per element, measured on the calibration machine at 160 ps per instruction: `System.arraycopy` and `Arrays.fill` 1; `Arrays.copyOf`/`copyOfRange` and array `clone()`, which allocate, 4; `Arrays.sort` of primitives 20 and of objects 50 per n·log2 n, also `Collections.sort` and `List.sort`; a list's `contains`, `indexOf`, `lastIndexOf`, `remove(Object)`, `removeAll`, `retainAll` and `Collections.min`/`max` 3; `addAll`, `toArray`, `Collections.reverse`/`shuffle` 2. In 1 375 RoboRumble robots these are the size-dependent calls in wide use (`arraycopy` in 128 robots, sorts in about 60). String operations, streams (at most 7 robots), regular expressions (11) and I/O keep the flat cost. Garbage collection isn't counted.
- **An outdated robot host is refused.** The server decides on skipped turns, the robot host's agent counts the work, so both must follow the same rules. A robot host built before the recalibration still counted 900 ps per instruction: BeepBoop seemed to need 1.2 ms per turn instead of 0.2 ms, skipped about 9 500 turns in 35 rounds against SandboxDT and lost, where in classic it skips almost none and wins 32 of 35 rounds. The robot host's `--describe` now reports its rules' version, and the runner refuses deterministic battles when it isn't the server's.
- Partly supersedes ADR 0005: deterministic mode skips turns, by work instead of time.
